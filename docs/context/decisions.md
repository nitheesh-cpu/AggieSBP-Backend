# Backend decision log

Format: decision, why, what was rejected, where, status. Dates are when the decision was made (from session history). Entries are grouped by area, so ids are not always in order; new entries take the next free number (D-048 next). Gotchas and fixed bugs are in `gotchas.md`; unfinished things are in `open-items.md`.

Ops facts that matter for deploys (branches, migrations, cron) are in `AGENTS.md` and `docs/admin-setup.md`. No secrets, hosts or IPs go in this file.

## AI professor summaries (`pipelines/professors/hierarchical_summarization/`)

### D-001: One TAMU AI request per professor  (2026-10-16)
**Decision:** `professor_request.py` builds ONE request holding all of a professor's deduped reviews, grouped by normalized course, newest first, each clipped to `SUMMARY_REVIEW_CLIP_CHARS` (default 600). If the input exceeds `TAMU_AI_MAX_INPUT_CHARS` (45000) it is split only by whole course groups; see `pipeline.py::_generate_part` for the output-budget and truncation handling. **Why:** the old design sent ~7 requests per professor (per-course requests, each with at most 2 HDBSCAN clusters; clustering gave ~1.6 clusters per course so it mostly split requests). The TAMU budget is a token budget, so repeated system prompts and output tokens are what burn it. About 5,100 requests replaced about 36,000. **Rejected:** HDBSCAN-cluster-based splitting for the TAMU path; a BART/extractive fallback summary when the request fails. **Where:** `professor_request.py`, `pipeline.py`, `ai_clients.py`. **Status:** active. The local HDBSCAN+BART path still exists only for runs without TAMU credentials.

### D-002: Courses with fewer than 3 reviews share an `OTHER` group; citations use short ids  (2026-10-16)
**Decision:** `MIN_COURSE_REVIEWS = 3`, `OTHER_GROUP = "OTHER"`. Claims from `OTHER` are routed back to the course of the reviews they cite. The model cites `r1..rN`; they are mapped back to real RMP ids in `professor_request.py`, and any claim citing an id not in that request is discarded. **Why:** full RMP ids cost ~8 output tokens each; the local citation check is the cheap, effective hallucination guard. A course with 2 reviews legitimately has no tips. **Rejected:** per-course requests for tiny courses. **Where:** `professor_request.py`, `response_schema.py` (strict pydantic, `extra="forbid"`). **Status:** active.

### D-003: Review statistics are computed in Python from raw reviews, not by the LLM  (2026-10-16)
**Decision:** `review_stats.py` computes would-take-again %, self-reported grade distribution, attendance %, textbook %, recent (last 730 days) vs older rating, each with an `_n` count. It reads RAW stored reviews before the text filter and dedup. **Why:** short or duplicate review texts still carry valid metadata, and numbers from an LLM are unreliable. **Where:** `review_stats.py`. **Status:** active.

### D-004: TypeSafe claim verification is opt-in and support-only; a failed TAMU request fails the professor  (2026-10-16)
**Decision:** `TypeSafeReviewJudge.from_env()` returns None unless `TYPESAFE_VERIFY` is on and a key is set. When on, a claim is rejected only for low support (`TYPESAFE_SUPPORT_THRESHOLD` 0.72); if TypeSafe gives no answer the claim is kept. A failed TAMU request leaves the professor unsummarized and retried next run; no fallback summary is saved. **Why:** the old overgeneralization/disagreement thresholds left 42% of overall summaries with zero complaints. The old BART fallback often quoted one review's first sentences. **Rejected:** saving a fallback on failure. **Where:** `ai_clients.py`, `pipeline.py`. **Status:** active.

### D-005: Structured summary fields are optional end to end; `other` keeps copying tips  (2026-10-16)
**Decision:** the pipeline writes `tldr`, `tips`, `review_stats`, `citations` (migration `pipelines/professors/migrations/001_structured_professor_summaries.sql`) and also copies tips into the legacy `other` column. The API probes whether those columns exist (`api/structured_summaries.py`) and the ORM columns are `deferred()`. **Why:** the API must deploy before the migration, and old extension/frontend versions still read `other`. New UIs hide `other` when `tips` is non-empty. The `attendance_policies` field is stored in the existing `policies` column (no new column). **Rejected:** removing the `other` copy; returning `other` from `/course/{id}` (it would surface legacy notes that page never showed). **Where:** `api/structured_summaries.py`, `database/base.py` (`ProfessorSummaryNewDB`), `pipelines/professors/upsert.py`. **Status:** active.

### D-006: Nightly review fetch queues summary rebuilds; it does not call the AI provider  (2026-11-17)
**Decision:** `upsert_reviews_and_summaries.py --fetch-only` fetches new RMP reviews (only for professors whose RMP count changed), clears their caches, and queues rebuilds in `admin_summary_rebuilds`. It first imports professors new on RMP. The threshold is shared via `summary_deferral()` (default 10% via `SUMMARY_MIN_NEW_REVIEW_PERCENT`). The queue row bumps `revision`/`changed_at` on conflict; the worker deletes a row only if both still match. **Why:** the owner wants control over AI spend; rebuilds run from the admin page/worker. It deliberately does not take the summary advisory lock (only generation needs it). **Where:** `pipelines/professors/upsert_reviews_and_summaries.py`, `review_sync.py`, `core/admin_worker.py`. **Status:** active. Detail in `docs/admin-setup.md`, `docs/admin-worker.md`.

### D-007: Run order puts professors teaching the current or next term first  (2026-10-16)
**Decision:** the summary run selects professors with sections in the current/next term before the rest, and regenerates only when at least `SUMMARY_MIN_NEW_REVIEW_PERCENT` (10%) new reviews exist. **Why:** the daily AI allowance should go where students look. **Where:** `upsert_reviews_and_summaries.py`. **Status:** active.

### D-008: Department inference for bare course numbers is evidence-first, never catalog-only  (2026-10-26)
**Decision:** `course_normalizer.py::infer_department_with_source` order: (1) registrar grade/section data shows this professor teaching that exact number in one subject; (2) exact department name to code; (1b) the only offering subject is one they teach under other numbers; (3) fuzzy dept-name match among subjects offering the number; (4) most common dept in their other reviews. Only 3-digit (or 6-digit run-together) numbers are inferred. Real department codes beat aliases (`COSC` is Construction Science). **Why:** the catalog lacks retired courses; an "only one subject offers N" rule produced SPAN218 for physicists. Exact department name outranks "taught subject" because grade rows name instructors as surname+initial and common names collide. **Rejected:** "only one subject in catalog offers N" fallback; querying `DepartmentDB` via the ORM. **Where:** `course_normalizer.py` (raw SQL `SELECT id, title, long_name FROM departments`), `pipelines/professors/backfill_course_departments.py` (dry run by default, `--apply` to write). **Status:** active.

## Honest data

### D-009: The API returns null for missing ratings and GPAs, never a made-up 3.0  (2026-10-17)
**Decision:** removed every `else 3.0` / placeholder fallback; missing ratings/GPAs are null and the UI shows "-" or "No data yet". `_review_quality(review)` is the mean of clarity and helpful ratings only; difficulty is a separate scale and is returned separately. `/professor/{id}` course cards use the per-course rating (`professor_summaries` row for that course, excluding the overall row), not the professor's overall. `/professors/compare` does the same. **Why:** a live review found "3.0" shown for unreviewed courses and the overall rating on every per-course card. **Rejected:** treating a stored 3.0 as a sentinel (`NULLIF(avg_gpa, 3.0)`). **Where:** `api/main.py`, `api/routers/professors.py`, `api/routers/discover.py`. **Status:** active. Two leftovers are in `open-items.md` (O-004). Tests: `tests/test_honest_api_values.py`.

### D-010: Course GPA falls back to an all-time weighted GPA and says so  (2026-10-17)
**Decision:** `/course/{id}` uses the last 4 semesters; if the course was not taught recently (for example renumbered) it falls back to an enrollment-weighted all-time GPA and returns `gpaScope: "recent"|"all"`, `gpaLastYear`, `enrollmentYear`, `sectionsTermCode`. Section attributes and department stats use "latest semester with data", not a hardcoded year. **Why:** CSCE 121 showed "GPA N/A, 0 sections" while professor cards had grades. Hardcoded years are a recurring bug class (grep for literal years when touching term logic). **Where:** `api/main.py` (`all_time_gpa` CTE). **Status:** active.

## Search

### D-011: Course search tolerates spacing, order and shorthand; CRN search is limited to recent terms  (2026-11-12)
**Decision:** `core/subjects.py::course_search_key()` compacts input (`acct 327`, `ACCT327`, `acct-327`, `327 acct` all become `ACCT327`) and `/courses` also matches `REPLACE(c.code,' ','') ILIKE :code_key`. Shorthand subjects map only when a number follows (`cs 121` becomes CSCE121). A search that is exactly 5 digits also matches courses with a section carrying that CRN in the newest 12 `term_code`s. **Why:** the #1 search-miss cause (26% of searches missed). CRNs are reused across years, so older terms return wrong courses. Product rule: "CRN just goes to the course". **Where:** `core/subjects.py`, `api/main.py` (`get_courses`). **Status:** active. Tests: `tests/test_course_search_key.py`.

### D-012: PSYC is searched and looked up as PBSI  (2026-11-16)
**Decision:** `RENAMED_SUBJECTS = {"PSYC": "PBSI"}` and `current_subject()` in `core/subjects.py`, applied in search, four course endpoints and as PBSI evidence in `explain_choice`. The frontend redirects `/course/PSYC###` to PBSI. **Why:** TAMU renamed the subject. Older grades/reviews filed under PSYC are NOT merged into PBSI (open). **Where:** `core/subjects.py`, `api/main.py`. **Status:** active.

### D-013: Professor name search accepts "Last, First Middle"  (2026-11-16)
**Decision:** `core/name_search.py::professor_name_condition(raw, key)`. With a comma: last name plus first initial only (middle names ignored; initial-only because RMP spellings differ, and it stops "Kim, Daniel" matching every Kim). Without a comma: every word appears in the full name in any order. A swapped profile ("FURTH HOWARD") is found by "Furth, Brett Howard". **Why:** this is the Howdy/registrar format students paste. **Where:** `core/name_search.py`, used by both professor search params in `api/main.py`. **Status:** active. Tests: `tests/test_name_search.py`.

### D-014: `GET /instructors/search` lists registrar instructors with no RMP profile  (2026-11-18)
**Decision:** `core/instructor_search.py` lists instructors teaching in recent terms, with courses and official GPA, even without a profile. The course details endpoint also attaches official grades when no profile matched. **Why:** about half of zero-result professor searches were such people. **Where:** `core/instructor_search.py`, `api/main.py`. **Status:** active.

## Professor identity (RMP profile to registrar instructor)

### D-015: A wrong match is worse than a miss; evidence decides, names only break ties  (2026-11-10)
**Decision:** `core/professor_identity.py` treats each registrar instructor (PIDM from `SectionInstructorDB.instructor_pidm`) as a `Person` with the subjects they taught and each RMP profile as a `Profile` with subjects/courses parsed from its reviews. A profile is attached only when review evidence points to this instructor and not to a same-name colleague ("rival", a different PIDM). Ties give no profile. With no evidence it attaches only when the name is exact and unique on both sides. Nicknames need evidence. `NAME_MATCH_THRESHOLD = 0.82`. Instructor key is `(name, pidm, campus)`. **Why:** same-name professors (two Yu Zhangs, two Cooper/Edwards cases) kept showing the wrong reviews; showing another person's reviews is worse than showing nothing. **Rejected:** name-only matching; picking the profile with more reviews; widening `choose_profile` with cross-listing evidence (a subagent tried it; the real bug was in the frontend and the change loosened matching). **Where:** `core/professor_identity.py`, `core/name_matching.py`, `core/subjects.py`. **Status:** active.

### D-016: Rivals use the stricter `_similar_person`; grade rows use `grade_row_matches`  (2026-11-18)
**Decision:** rivals (who only ever block, never attach) must have equal joined surnames or a shared whole part, and first names that agree exactly, by initial, via a nickname line, or via `_spelling_variant`. A middle initial counts only when that person's first given name is also an initial. Grade rows ("LAST I") match on the registrar name only (`name_matching.grade_row_matches`); a row that fits two College Station instructors goes to neither. **Why:** before commit eac5eb0 "Brian A. Anderson" blocked 49 exact-name matches for "Arden Anderson". Fixed "SMITH D" to John D. Smith, "LI W" to Wei Liu. **Accepted cost:** if `gpa_data` truncates long surnames those rows are lost. **Where:** `core/professor_identity.py`, `core/name_matching.py`, `api/main.py` (`get_course_professors_details`). **Status:** active.

### D-017: Cache key for course professor details includes a hash of the matching source  (2026-11-10)
**Decision:** `MATCHING_VERSION = sha1(professor_identity.py + name_matching.py + subjects.py)[:10]`, passed as `@cached(ttl=TTL_WEEK, version=PROFESSOR_MATCHING_VERSION)` on `get_course_professors_details`. **Why:** a correct fix was invisible for a week because the exact URL the extension calls was cached. Any edit to those three files (even a comment or whitespace) starts that cache cold, and big courses then take 5-25 s on first visit. **Rejected:** a manually bumped constant; clearing Redis by hand after each deploy. **Where:** `core/professor_identity.py`, `core/cache.py::_generate_cache_key`. **Status:** active. See G-014.

### D-018: Assumption-based matches are proposals that the admin confirms (instructor links)  (2026-11-18)
**Decision:** confident evidence-backed matches stay automatic. Matches that rest on an assumption (a middle initial standing in for the first name, a swapped name fitting only via an initial, near misses) are never auto-applied. They become proposals in `instructor_profile_links` (migration 005; statuses proposed/confirmed/rejected; a confirmed row with no profile means "no RMP profile"). Course pages apply a confirmed link first and never pick a rejected profile. Decided pairs are never re-proposed. Routes: `/admin/instructor-links*` (`routers/admin_links.py`, `core/instructor_links.py`). Every proposal carries `courseOverlap` and department so the admin can spot married couples and same-subject namesakes. **Why:** owner's rule, after "Natalie M. Johnson" was once linked to "Matthew Johnson". **Where:** `core/instructor_links.py`, `core/professor_identity.py` (`needs_course`, `swapped_needs_course`), `pipelines/professors/unmatched_instructors.py`. **Status:** active. Swapped RMP names went through three stages: auto-match with evidence (6673845), course-level evidence required (eac5eb0), proposal-only for the middle-initial case (8f1ee01).

### D-047: The TAMU AI review's confident non-matches are bulk-rejected; an exact shared course protects a candidate  (2026-11-19)
**Decision:** `qualifies_for_ai_rejection` (`core/instructor_ai_report.py`) rejects pending candidates the AI rated "very unlikely" (a shared subject does not override it) or "unlikely" (unless the profile has reviews in a subject the instructor teaches); anything else needs a clear language-versus-quantitative department mismatch, which works without an AI report. A high rating or an exact course in common (`courseOverlap`) always protects. The admin runs `GET/POST /admin/instructor-links/ai-reject` (preview, then a token-checked confirm); the apply step rechecks only `courseOverlap` on the stored row. **Why:** reviewing ~900 pending links by hand is not realistic, and a wrong rejection is reversible (Rejected tab, undo) while a wrong confirmation shows another person's ratings. **Rejected:** rejecting "possible" or "unclear" ratings, and rejecting from the review script itself (it would need cache invalidation and skip the preview). **Where:** `core/instructor_ai_report.py`, `core/instructor_links.py::reject_ai_candidates`, `pipelines/professors/review_instructor_links.py` (prompt tells the model these ratings act automatically). **Status:** active.

### D-019: Instructors outside College Station and Galveston retry at the College Station RMP school  (2026-11-18)
**Decision:** `match_instructor_any_campus` retries sections with `university_id` None (McAllen, Dallas, Fort Worth, DC, partner colleges; ~385 never-checked instructors) at College Station's RMP school with `name_alone=False`, so review evidence is required. **Why:** those instructors were never checked at all. **Where:** `core/professor_identity.py`, `core/campuses.py`. **Status:** active.

### D-020: Course endpoint and the unmatched report share one matcher  (2026-11-18)
**Decision:** `match_instructor` / `match_instructor_any_campus` serve both `GET /sections/{term}/course/{code}/professors/details` and `pipelines/professors/unmatched_instructors.py`. `explain_choice` returns the decision plus a reason per rejected profile; `choose_profile` is `explain_choice(...)[0]`. **Why:** the report must not drift from the site. **Where:** `core/professor_identity.py`. **Status:** active. Keep one decision path.

## Duplicate professors (merges)

### D-021: Merges are an alias table plus SQL views; raw tables are never edited  (2026-11-16)
**Decision:** `professors`, `reviews`, `professor_summaries_new` stay exactly as the RMP pipelines write them. `professor_aliases(alias_id, canonical_id, evidence, status)` plus views `professor_canonical_ids`, `professors_merged`, `reviews_merged`, `professor_summaries_merged` (migration `002_professor_aliases.sql`). Only `confirmed` rows take effect; undo is setting `rejected` (never re-proposed). The API reads the views (many `_merged` references in `api/main.py`, `routers/discover.py`, `routers/professors.py`); pipelines write the tables. Old ids resolve through `resolve_professor_id()`. **Why:** undo is one row, pipelines stay simple, data matches RMP. **Rejected:** the first subagent's design that deleted alias rows, moved reviews and folded aliases into the upsert functions. **Where:** `database/migrations/002_professor_aliases.sql`, `core/professor_merges.py`, `core/professor_identity.py`. **Status:** active. Re-run migration 002 after adding a column to professors/reviews/summaries (views are built from column lists).

### D-022: Merge rules are narrow on purpose  (2026-11-16)
**Decision:** a merge needs the same campus, identical first names or a safe spelling edit (added "h", doubled consonant), a shared reviewed COURSE (not just subject), at most one compatible registrar namesake that has a PIDM and an exact name, matching suffixes, and direct evidence for every pair in a group (no hub chains). One-vowel differences (Abigail/Abigael) merge only with registrar confirmation and the evidence text starts "CHECK:". Never merged: nicknames, initials, empty profiles, gendered or different-name pairs (Francis/Frances, Jesse/Jessie, Terry/Terri). Real data: 75 merges, 0 ambiguous out of 6,288 profiles. Proposals are made by cron (`merge_duplicates.py --propose`) and confirmed by a human in `/admin/merges`. `chain_problem` refuses chained merges. **Why:** owner: "missed duplicates over wrong merges"; a false merge shows one person's reviews on another's page. **Rejected:** loosening to "same name = same person" (the medium tier in the first audit was mostly different people). **Where:** `core/professor_identity.py` (`name_variant`, `duplicate_evidence`, `plan_profile_merges`), `core/professor_merges.py`, `tests/test_professor_merge.py`. **Status:** active.

### D-023: Merge confirm/reject goes through the admin API, not SSH  (2026-11-16)
**Decision:** `/admin/professor-merges` (list, confirm, reject; `X-Admin-Key`) shares `core/professor_merges.py` with the CLI. Status changes invalidate only the affected professors' caches. A trigger in migration 004 marks both sides of a merge for a summary rebuild. **Why:** the owner prefers a web UI over pasting ids on the VM. **Where:** `api/routers/admin.py`, `core/professor_merges.py`. **Status:** active.

## Prerequisites and planner

### D-024: Prerequisite trees replace `courses.prerequisite_groups`  (2026-11-06)
**Decision:** `courses.prereq_tree`, `coreq_tree`, `prereq_parse` (JSONB; migration `pipelines/courses/migrations/001_prereq_trees.sql`) are built by `pipelines/courses/parse_prereqs.py` in this order: rule parser, then TAMU AI in batches of 10 (validated), then the legacy groups (always low confidence). Rows are skipped when `text_hash` (normalized text + `PARSER_VERSION`) is unchanged; bump `PARSER_VERSION` in `prereq_parser.py` when parser logic changes. `concurrent: true` means may be taken the same term. A missing tree means no requirement. `/course/{id}` still returns `groups` for compatibility. **Why:** the scraper's groups are wrong for many courses (CSCE 411 "221 and 222" stored as one OR group, mojibake duplicates). **Rejected:** falling back to `prerequisite_groups` in new code. **Where:** `pipelines/courses/prereq_parser.py` (node shapes documented at the top), `parse_prereqs.py`, `api/routers/prereqs.py`. **Status:** active. Re-run after any catalog re-scrape. Tests: `tests/test_prereq_parser.py`, `tests/test_prereq_api.py`.

### D-025: LLM prereq output is validated hard, but harmless slips are coerced  (2026-11-06)
**Decision:** `validate_tree` rejects any tree naming a course not in the source text. `coerce_llm_node` first fixes harmless slips (unknown condition kind, approval written as condition, grades like "C-", `concurrent: null`). `lint_tree` flags and/or mix-ups; `RETRYABLE_ISSUES` get one retry with a hint, else the row is low confidence. `finalize` is shared by the rules, LLM and legacy paths. **Why:** the validator caught the LLM inventing SPAN 300/400; making it stricter on slips just costs fallbacks. **Where:** `parse_prereqs.py`, `prereq_parser.py`. **Status:** active.

### D-026: Planner state is two JSON documents per user with revision-checked saves  (2026-11-06)
**Decision:** `api/routers/planner.py` stores `record` and `plan` JSONB in one row of `user_planner_state` (migration `database/migrations/001_user_planner_state.sql`), at `GET /users/me/planner`, `PUT /users/me/planner/record` and `/plan`. PUT takes `{record, base_rev}` or `{plan, base_rev}`; a stale `base_rev` returns 409 with the current document so the client merges and retries. Limits `MAX_COURSES=400`, `MAX_PLAN_BYTES=100_000`. **Why:** requirements need joins with existing tables and the dataset is small (JSONB in Postgres over Mongo). **Rejected:** the May degree-planner tables and `/planner/plans*` routes (gone; do not revive). The product is a supplemental schedule tool, not a degree audit (parent repo decision). **Where:** `api/routers/planner.py`, `tests/test_planner_api.py`. **Status:** active. `docs/degree-planner-plan.md` (parent repo) is stale vs this.

## Discover (UCC, Fit My Schedule, electives)

### D-027: Fit and UCC read `sections.attributes_text`, not `section_attributes_detailed`  (2026-05-14)
**Decision:** `routers/discover.py` splits the pipe-delimited `attributes_text` with `regexp_split_to_table(s.attributes_text, '\|')`. `/ucc` filters sections in a CTE before the LATERAL split and the professor ILIKE join. `ucc-fit-candidates` is the lightweight GPA-only endpoint the Fit page must call (not the heavy `/ucc`). **Why:** in May `section_attributes_detailed` was empty for the terms in use, which emptied the dropdown and all UCC results. The CTE order stops row multiplication that made the request hang. **Where:** `routers/discover.py`. **Status:** active. `pipelines/sections/upsert.py` now writes the detailed table too; consolidating is open (O-007).

### D-028: Easiness score renormalizes over the components that exist  (2026-11-09)
**Decision:** `calculate_easiness_score(avg_gpa, avg_difficulty, avg_rating)` in `routers/discover.py`: weights GPA/4*0.5, (5-difficulty)/4*0.3, rating/5*0.2; a component counts only if it is truthy and greater than 0 (0 means "no data"); divide by the sum of present weights; 0 if none. Callers pass `avg_gpa` as None or a float, not `avg_gpa or 0`. `hasGradeData = avg_gpa is not None and avg_gpa > 0` drives the "no grade data" label. **Why:** treating missing GPA as 0 capped ungraded professors at 50, so "35" meant "no grade history" rather than "hard". **Accepted:** ratings-only scores can outrank GPA-backed ones; the label is the only signal (open, O-008). **Where:** `routers/discover.py`, `tests/test_easiness_score.py`. **Status:** active.

### D-029: UCC cache TTL depends on the seat filter  (2026-10-26)
**Decision:** `cached(ttl, ttl_for=...)` in `core/cache.py`; `_ucc_ttl` returns `TTL_15MIN` when `seats != "any"` and `TTL_WEEK` otherwise. **Why:** seat status refreshes about every 15 minutes; a flat weekly TTL would show stale open/full results. **Where:** `core/cache.py`, `routers/discover.py`. **Status:** active.

### D-030: GPA boosters have a fixed definition  (2026-11-09)
**Decision:** `GET /discover/{term}/gpa-boosters`: undergrad (`course_number < '500'`), student-weighted GPA at least 3.5 (`min_gpa`), since 2022, at least 100 students, offered in the term. Excludes non-regular suffixes (`_NOT_REGULAR_SUFFIXES`: seminars, internships, research, independent study, special topics, theses). Calls `_discover_rows(..., limit=limit*8)` so several professors per course survive. **Why:** those course types have inflated GPAs but are not real choices. **Where:** `routers/discover.py`. **Status:** active. Some major-restricted courses still slip in (O-009).

### D-031: Special topics are identified by the SECTION title, and exam meetings are not class times  (2026-11-10)
**Decision:** fit-sections returns a per-section `title` (SQL `json_build_object`, `DiscoverFitSection.title`, and the constructor kwarg); the frontend splits "SPTP:" topics from it. Meetings with `meeting_type` like `exam` are excluded from class times. **Why:** without `title` topics silently do not split; exam slots (729 in Spring 2027) caused false conflicts. **Where:** `routers/discover.py`. **Status:** active. See G-017, G-018.

## Seat alerts and push

### D-032: Push endpoints are allowlisted; sends have a timeout; only 404/410 removes a subscription  (2026-11-09)
**Decision:** `core/push_endpoints.py::is_allowed_push_endpoint()` accepts only https, no userinfo, port 443, host equal to or under `fcm.googleapis.com`, `updates.push.services.mozilla.com`, `notify.windows.com`, `push.apple.com`. Enforced in three places: the `PushSubscriptionRequest` validator in `routers/users.py`, `core/notifications.py`, and `collectors/section_watcher.py`. `PUSH_TIMEOUT_SECONDS = 10` goes to pywebpush. The watcher deletes a subscription only on 404/410 or a non-allowlisted endpoint; every attempt is logged to `push_notifications` (migration 003, no foreign keys on purpose, one batched INSERT with `SET LOCAL statement_timeout='5s'`, logging failures never block alerts). **Why:** the endpoint was any string and the server POSTs to it (SSRF/internal-network probe by any free account). The watcher used to unsubscribe people on timeouts and VAPID errors. **Where:** `core/push_endpoints.py`, `core/notifications.py`, `collectors/section_watcher.py`, `routers/users.py`. **Status:** active. Test: `tests/test_push_endpoints.py`.

### D-033: Seat-watch cap is 100 per user, not removed  (2026-11-16)
**Decision:** `max_tracked_sections_per_user = 100` (`core/config.py`, was 20). `POST /users/tracking` returns 422 at the cap. **Why:** the watcher reads open/closed status the scraper already stores in one joined query, so more watches cost almost nothing; the cap only stops scripted flooding of the watch table. **Where:** `core/config.py`, `routers/users.py`. **Status:** active.

### D-034: Account deletion is one DB transaction, then best-effort external cleanup; a retention purge runs nightly  (2026-11-17)
**Decision:** `DELETE /users/me`: all DB deletes in ONE transaction, then Redis tracker cleanup (a `{term}:{crn}` member is removed only when its tracker set is empty), then SuperTokens `delete_user`, then `revoke_all_sessions_for_user`. A DB failure rolls back with 500 "Nothing was changed"; a SuperTokens failure after commit returns 502 and keeps the session so the user can retry. `core/user_data.py::USER_DATA_TABLES` lists the tables; coverage-guard tests fail if any table with a `user_id` column is not listed. `pipelines/maintenance/purge_expired_data.py` deletes push log rows after 180 days, seat watches 30 days after `terms.end_date` (else after 365 days), finished admin jobs after 90 days (keeping the newest 100). **Why:** the privacy policy promises these exact periods. **Rejected:** purging accounts, planner state, schedules or push devices. **Where:** `core/user_data.py`, `pipelines/maintenance/purge_expired_data.py`. **Status:** active. Changing the constants means updating the site's `/privacy` page.

## Admin, caching, rate limits

### D-035: Admin endpoints fail closed behind `X-Admin-Key`  (2026-10-28)
**Decision:** `core/admin_auth.py::require_admin_key`: header `X-Admin-Key` vs the `ADMIN_API_KEY` setting, `secrets.compare_digest`, 503 when the key is unset (endpoint disabled), 401 on missing or wrong key. It guards `DELETE /cache/clear` and every `/admin*` route. `tests/test_admin_auth.py` walks `app.routes` for all `/admin*` routes and asserts 401/503 behavior and that each route's dependency tree includes `require_admin_key`, so a new admin route without the dependency fails the test. **Why:** an unauthenticated agent once wiped the whole prod Redis cache (6,547 keys). `GET /cache/status` stays public (read-only). **Where:** `core/admin_auth.py`, `api/routers/admin*.py`, `api/main.py`. **Status:** active.

### D-036: Server-side rendering traffic bypasses the per-IP rate limit with an internal key  (2026-11-17)
**Decision:** `InternalExemptLimiter` (subclass of slowapi `Limiter`, overrides `_check_request_limit`) skips all limits when `X-Internal-Key` equals `INTERNAL_API_KEY` (`hmac.compare_digest`) and sets `request.state.view_rate_limit = None`. An unset or empty key exempts nothing. **Why:** Vercel SSR calls come from a few shared IPs against a ~60/min/IP limit, so Googlebot crawls got error pages. slowapi's `request_filter`/`exempt_when` cannot see the request. **Where:** `api/main.py`, `core/config.py` (`internal_api_key`). **Status:** active.

### D-037: Cache invalidation is targeted by path pattern, plus website revalidation  (2026-11-17)
**Decision:** `core/cache_invalidation.py` (`invalidate_professors`, `invalidate_courses`, `invalidate_all`, strict mode). Redis keys are `api:<path>:<hash>`; one SCAN of `api:*` matches all patterns client-side (no KEYS), deletes in batches of 500, more than 200 course codes collapse to `/course/*`. `invalidate_professors` widens ids with confirmed aliases both ways. It then POSTs page paths to the site's `/api/revalidate` (needs `SITE_REVALIDATE_URL` and `REVALIDATE_SECRET`, else skipped with a debug log). `/admin/cache/clear` uses `strict=True` so a Redis failure is an error, not "skipped". Sections endpoints (15 min), `/terms`, `/departments*` and `/users/*` are intentionally not touched. **Why:** the old whole-cache clear made every page slow after each change. **Where:** `core/cache_invalidation.py`, `core/admin_worker.py`, `routers/admin*.py`, upsert pipelines. **Status:** active. Wiring details in G-023.

### D-038: Summary rebuilds run from a Postgres-backed job queue and a separate worker  (2026-11-16)
**Decision:** `core/admin_jobs.py`, `core/admin_worker.py` (`python -m aggiermp.core.admin_worker`, systemd `aggiesbp-summary-worker`), `core/summary_lock.py`, `routers/admin_jobs.py`, migration `004_admin_jobs.sql` (needs 002). Jobs survive restarts; enqueue takes an advisory transaction lock, maps aliases to canonical ids, returns the existing job if covered and 409 on partial overlap; at most 500 professors per job. The worker and the cron summary run share a Postgres summary lock. Redis is checked before AI work and a batch stops if cache clear fails (never save summaries without clearing stale pages). Quota exhaustion stops the job as `quota_exhausted` until a manual retry. The job log stores only ids and outcomes, never review text or prompts. **Where:** files above, `docs/admin-worker.md`, `docs/admin-monitoring.md`. **Status:** active.

### D-039: Cronitor status is proxied server-side  (2026-11-17)
**Decision:** `core/admin_monitoring.py` calls the Cronitor API with Basic auth; the key is never returned or logged. An outage gives `unavailable`, then `stale`, never `healthy`. Missing config gives `not_configured`. Cached 30 s per process (health 15 s). Add monitors by appending to `CRONITOR_MONITOR_KEYS`. **Where:** `core/admin_monitoring.py`. **Status:** active.

## Database, deploys and pipelines

### D-040: Migrations are plain idempotent SQL applied by hand, in order  (2026-11-06)
**Decision:** no migration framework. App migrations: `src/aggiermp/database/migrations/001`-`005`; course migrations: `pipelines/courses/migrations/`; professor migrations: `pipelines/professors/migrations/`. Every statement is safe to re-run. Run as the app's DB user (not the `postgres` superuser, or views end up owned by postgres). Apply migrations BEFORE deploying code that needs them, except 002 which old code tolerates, so running it early is always safe. New code skips missing optional tables via `to_regclass`; only the summary job pages and worker require 004. **Why:** small team, one VM. **Where:** the folders above, `docs/admin-setup.md`. **Status:** active.

### D-041: The GPA pipeline paces itself and fetches only what is missing  (2026-11-16)
**Decision:** `pipelines/gpa/anex_scraping.py` verifies TLS with certifi, orders terms by calendar year (`SEMESTER_ORDER = SPRING 1, SUMMER 2, FALL 3`), paces requests at `DEFAULT_REQUEST_INTERVAL = 8.0` s plus up to 50% jitter, waits out IP blocks with cooldowns of 10/20/40/60 minutes (interval +50% each time) and gives up after 6 consecutive blocks keeping the checkpoint. Default mode requests only courses taught in a published term with no `gpa_data` for it and with some GPA history; `--include-no-history` and `--full` widen it. Upserts dedupe ids, run in batches of 2,000 and a failed batch raises (non-zero exit for Cronitor). Long runs go through `pipelines/gpa/run_in_tmux.sh`. **Why:** anex.us IP-blocks after about 10 quick requests; Fall 2025 had 700 courses with GPA vs ~2,400 for earlier falls because of the old term order. **Rejected:** more concurrency. **Where:** `pipelines/gpa/`, `core/gpa_progress.py`. **Status:** active.

### D-042: `requirements.txt` is the reliable install path; torch is pinned per architecture  (2026-11-17)
**Decision:** `torch==2.5.1; platform_machine == "aarch64"` (the `+cpu` builds are x86_64-only), sympy pinned to 1.13.1, torchvision removed, `requires-python >=3.11`. `pyproject.toml` has an incomplete dependency list. **Why:** the production VM is ARM. **Where:** `requirements.txt`. **Status:** active, but the VM venv is Python 3.13 and torch 2.5.1 has no aarch64 cp313 wheel (O-011).

### D-043: Course catalog scraper reads undergraduate AND graduate catalogs  (2026-11-16)
**Decision:** `CATALOG_LEVELS = ("undergraduate","graduate")`, `get_all_catalog_departments()` in `pipelines/courses/course_catalog_scraping.py`; the "(CODE)" suffix in department link text is optional. **Why:** CSCE 614, MEEN 205, HIST 255 etc. were missing because only the undergraduate catalog was read (first, wrong hypothesis was missing grade history). `upsert_courses.py` is not run from CI; it runs from server cron. **Status:** active. See G-021.

## Errors and security posture

### D-044: Clients never see raw exception text  (2026-05-13)
**Decision:** `_db_error(e, context)` logs with `exc_info` and returns a generic 500 "An internal server error occurred." Copies live in `api/main.py`, `routers/discover.py`, `routers/users.py`, `routers/professors.py`. A handler that raises its own `HTTPException` inside `try` needs `except HTTPException: raise` first. **Why:** 34 handlers used `detail=f"Database error: {str(e)}"`, which can leak connection strings and schema. **Status:** active. A few health endpoints still return `str(e)` (O-005).

### D-045: Sessions are header-only, which is why wildcard Vercel CORS is tolerable  (2026-10-30)
**Decision:** SuperTokens uses `get_token_transfer_method -> "header"` and `anti_csrf="NONE"` (`api/main.py`). CORS allows `^https://.*\.vercel\.app$` plus localhost (`cors_allow_vercel_previews`, default True). **Why:** the preview deployments need the API. This is only safe because tokens are never cookies. **Rejected:** switching to cookie sessions without revisiting CORS (every Vercel site would become a credentialed origin). **Where:** `api/main.py`, `core/config.py`. **Status:** active, but since 2026-11-24 production sets `cors_allow_vercel_previews=false`: the site moved to `aggiesbp.com` (parent D-023), Vercel no longer builds previews, and the wildcard let any `*.vercel.app` site make CORS calls. Production origins come from `SUPERTOKENS_WEBSITE_DOMAIN` plus `cors_origins_extra`. See G-010.

### D-046: Google OAuth is registered only when both client id and secret are set; DB URL comes from Settings  (2026-05-13)
**Decision:** the provider is added only if both values exist; `database/base.py` builds the engine from `settings.database_url` (which `quote_plus`es user and password), not `os.getenv`. **Why:** `str(None)` was the truthy string "None", and `POSTGRES_*` aliases in Settings could disagree with direct env reads. **Where:** `api/main.py`, `core/config.py`, `database/base.py`. **Status:** active.
